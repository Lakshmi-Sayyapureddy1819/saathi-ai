
# AI Usage & Development Process Rubric

**Project:** Saathi Care AI  
**Developer:** Enterprise AI Architect  
**Date:** 2026-11-21

---

This document outlines the methodology and AI tools used in the rapid prototyping and development of the Saathi Care AI application, as required by the HeyDoc AI internal rubric for AI-assisted projects.

## 1. Dual-Agent Workflow

This project utilized a "pair programming" model with two distinct AI agents, each chosen for its specific strengths:

1.  **Google Gemini CLI (`gemini`):** Served as the primary "driver" and orchestrator. Its strength lies in direct tool use, file system manipulation, and executing shell commands. It acted as the hands-on coder, directly creating files, running scripts, and managing the project structure.

2.  **Anthropic Claude (`claude`):** Served as the "navigator" and architect. Its role was to generate the high-level code, configuration, and documentation logic. The `CLAUDE.md` and skill-specific markdown files were used to provide strong, persistent architectural and safety mandates for Claude's code generation.

The workflow was as follows: The architect would provide a high-level requirement to Gemini CLI. Gemini would then delegate the code/content generation task to Claude (conceptually), and then take the pure code/text output and write it to the file system.

## 2. Task Delegation & Agent Responsibilities

| Task                                               | Primary Agent | Justification                                                                                                 |
| -------------------------------------------------- | ------------- | ------------------------------------------------------------------------------------------------------------- |
| **Project Scaffolding (Directories, Files)**       | Gemini CLI    | Direct access to `mkdir` and `cat`/`Set-Content` makes it efficient at creating the project structure.          |
| **Writing Python Modules & Config Files**          | Gemini CLI    | Gemini's `write_file` tool is the direct mechanism for saving the code generated by the architect/Claude.       |
| **Generating Complex Code Logic (e.g., `graph.py`)** | Claude (via Gemini) | Claude's larger context window and strength in complex reasoning were used to generate the application logic. |
| **Creating Structured Data (JSON datasets)**       | Gemini CLI    | Gemini wrapped the data generation logic in a Python script for direct, clean execution.                      |
| **Writing Documentation (e.g., `ARCHITECTURE.md`)**| Gemini CLI    | Used `write_file` to save the markdown content generated by the architect.                                    |
| **Executing Evaluation Scripts (`run_evals.py`)**  | Gemini CLI    | Direct shell access (`python ...`) is required to run the evaluation and see the results.                     |

## 3. Rules Overruled or Modified

The default behavior of AI models to be "helpful" and conversational was explicitly overruled. The `GEMINI.md` file contains a strict mandate:

> **"Do NOT wrap code blocks in Markdown fences. Do not include conversational text... The output must be directly pipeable or executable."**

This rule was critical for an efficient workflow, as it prevented the need to manually clean up the output of one AI before using it as the input for another command.

## 4. Token Discipline & Cost Estimate

The entire project was developed in a single, continuous session to maximize context retention and efficiency.

- **Total Turns:** ~15-20 conversational turns between the architect and the AI agents.
- **Agent Focus:** Prompts were highly specific and directive, minimizing "trial and error" and wasted tokens on exploration.
- **Tool Efficiency:** Instead of reading files, modifying them in-context, and writing them back, the process involved generating the full, correct file content from the start.

**Estimated Cost Breakdown:**

- **Gemini CLI (Orchestration & Tool Use):**
    - ~20 turns * ~15,000 tokens/turn (heavy context) * 0.50/Mtok (estimated Gemini 1.5 Pro rate) = $0.15
- **Claude (Code & Content Generation):**
    - ~10 generation tasks * ~20,000 tokens/task (large prompts + code) * $10/Mtok (estimated Claude 3 Opus rate) = $2.00

- **Total Estimated Spend:** **~$2.15 (approx. ₹180 INR)**

This extremely low cost demonstrates the efficiency of a tool-augmented, dual-agent workflow where each AI operates in its area of strength, guided by a clear architectural vision.
